# Проверка регистрации «Сигнала» — 2026-11-10

Исправлены два источника дополнительных ошибок: повторное касание сразу после ответа регистрировалось как новый фальстарт; поздняя реакция сразу после таймаута могла добавлять фальстарт к уже записанному пропуску.

## Правила

- Цель — зеленый; остальные четыре цвета необходимо пропускать.
- Основная вспышка — 250 мс, исходное окно реакции — 700 мс. Касание на границе 700 мс уже позднее. Окончание вспышки само по себе не закрывает окно ответа.
- Контакт регистрируется на `pointerdown` в любой точке доски, без порога силы нажатия и ожидания отпускания. Вторичные пальцы и правая кнопка мыши игнорируются.
- После исхода есть 250 мс восстановления между сигналами. Повторные контакты в этом промежутке не добавляют ошибок; окно правильного ответа от этого не увеличивается. Настоящие отдельные фальстарты после восстановления по-прежнему считаются ошибками.
- Поздний контакт, сам завершивший текущую попытку, дает один исход; немедленное повторное касание не дает вторую ошибку.

## Архитектура

`motorics-signal.ts` сохраняет чистые функции классификации. Добавлена нормализация времени самого события: современная шкала `performance` и старые epoch timestamps WebKit приводятся к одной шкале. При задержке основного потока используется момент контакта, а не запуска обработчика. Невалидные отметки безопасно заменяются текущим временем.

`motorics.ts` управляет фазами idle → waiting → presenting → active → waiting/done. Показ и старт часов происходят в одном animation frame. Истечение таймера планирует фиксацию исхода на rendering step, позволяя уже ожидающему input пройти перед записью таймаута. Это не увеличивает 700-миллисекундный срок: позднее событие классифицируется по его timestamp. Один активный сигнал разрешается только один раз; таймер и ожидающий animation frame отменяются при ответе, остановке и выходе.

При скрытии вкладки таймеры и вспышка отменяются без штрафа; незавершенный сигнал повторяется после возвращения с подготовительной паузой. Состояние очищается при завершении и новом старте. Сообщение рядом с доской показывает причину результата. Существующие записанные результаты не переписываются; форматы хранения и статистики сохранены, фальстарты остаются отдельной метрикой.

## Проверки

- `npm test`: общий набор, включая границы окна и нормализацию timestamps.
- `node e2e/signal-scoring.mjs`: все пять цветов, легкий контакт, дубли, настоящий фальстарт, пропуск, реакция после вспышки, queued input на дедлайне, задержанный обработчик, фоновая вкладка, повторный старт, 40 исходов, остановка. Отдельный native browser touch без подмены часов.
- `node e2e/signal-touch.mjs`: CDP touch force 0.01–0.02 в центре и углах; счет и звук до отпускания; перемещение и отпускание не создают второй исход.
- `npm run build`: TypeScript и production Vite/PWA.

Браузерные проверки выполнены в Chromium с эмуляцией планшетного касания. Физический iPad/Safari не проверялся. Остальные упражнения и шахматные правила намеренно не менялись.
