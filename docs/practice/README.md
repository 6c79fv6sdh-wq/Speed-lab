# Игровой экран без постоянной прокрутки

Рабочая область открывается автоматически при входе в упражнение, ещё до «Старт»/«Начать». Её размеры и положение привязаны ко всей видимой области visualViewport, включая изменения браузерных панелей на планшете. «Поток сложения», уже активные упражнения дневного плана и возобновлённые занятия также поддерживаются. До начала можно нажать «Играть на одном экране». Кнопка «← Настройки и разделы» возвращает обычную страницу, не пересоздавая упражнение. Escape возвращает страницу, кроме случаев, когда упражнение использует его для отмены премувов.

Задание и основные действия находятся вместе. Настройки и подробные показатели остаются на обычной странице. Для реальной шахматной доски используется штатное вычисление размера, включая координаты, а не CSS-масштабирование. Цвет клеток, фигуры, таймеры и алгоритмы заданий не менялись. Смена размера Snapshot обрабатывается существующим механизмом повторного показа без штрафа.

MathLab:
- Компактные блоки задания, числовые кнопки и подтверждение; на широком экране — соседние колонки.
- В «Плюсах и минусах» два графических поля и одна общая клавиатура. После ввода количества плюсов выбирается поле минусов. Каждое поле можно выбрать вручную. После проверки числовая клавиатура уступает место результату и «Далее». Проверка и сохранение ответов прежние.
- В «Дострой десятку» числовые ответы 0–18 без экранной клавиатуры; после сборки десятки показывается компактное выражение с ответом, «Отменить перемещение» возвращает модель коробок. Мысленный режим сохраняет свои отдельные поля.
- В «Что ценнее?» после проверки группы компактно показывают стоимость, чтобы результат и «Далее» оставались видимыми.

Snapshot: доска, панель исчезнувших фигур и «Готово»/«Дальше» находятся в одной рабочей области. На портретном телефоне фигуры расположены сбоку от доски. Выбор уровня скрыт только во время активного задания, когда он и так заблокирован.

Реализация: `src/core/practice-view.ts`, интеграция в `src/main.ts`, локальные стили в `src/styles.css` и `src/modules/mathlab/styles.css`. Очистка восстанавливает overflow, ARIA и удаляет обработчики. Клавиатурный фокус остаётся в игровой области. Использованы CSS/dvh и visualViewport, без Fullscreen API, зависимостей или запросов разрешений.

Проверки:
- `node e2e/practice-layout.mjs`: MathLab, реальные размеры задания/ответов/подтверждения/следующего задания и отсутствие прокрутки; 320×568, 390×844, 820×1180, 844×390, 1440×900.
- `node e2e/practice-chess.mjs`: Snapshot уровня 5, «Готово»/«Дальше», четыре доски скана конём, «Сигнал» и премувы; первые четыре размера.
- `npm run test:math`: полный MathLab, маршрутизация, настройки, сохранение, возврат к шахматам.
- `CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium node e2e/touch.mjs`: прежние жесты доски и премувы обеими сторонами.
- `node e2e/addition-sound.mjs`, `node e2e/signal-scoring.mjs`: звук и классификация сигнала.
- `npm test -- --maxWorkers=2`, `npm run build`.

Снимки находятся в `screenshots/`. Проверено Chromium, в том числе с эмуляцией касаний; физический iPad/Safari не проверялся. При экстремально малом окне, увеличенном системном шрифте или открытой клавиатуре сохранена возможность прокрутки вместо обрезания содержимого. Длинные результаты и справку можно читать в обычном режиме.

Планшетные проверки: `node e2e/tablet-viewport.mjs` — 1024×768, 1180×820, 820×1180 и 768×1024, с уменьшением видимой области, смещением панели браузера и сохранением прогресса. Проверка Chromium имитирует изменения visualViewport; физический Safari остаётся отдельной проверкой.
